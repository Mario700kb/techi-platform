# TECHI Platform V1.0 Release Checklist

Status: release candidate for internal deployment.

## Backend Readiness

- FastAPI application starts from `backend/app/main.py`.
- API prefix is `/api/v1`; OpenAPI docs are available at `/api/v1/docs`.
- Health endpoint is available at `GET /health`.
- Auth, roles, scoped access, devices, alerts, audit, enrollment tokens, bootstrap, and agent package endpoints are wired in `backend/app/api/v1/api.py`.
- Websocket route is enabled at `/ws/devices`.
- Background workers start on application startup:
  - realtime event publisher
  - device reconciliation worker
  - SQLite dev schema compatibility guard
  - bootstrap owner creation when configured

## Frontend Readiness

- React/Vite app builds with `npm run build`.
- Sidebar version marker displays `v1.0`.
- Core pages are present:
  - Dashboard
  - Devices
  - Clients
  - Enrollment Bootstrap
  - Agent Packages
  - Inventory
  - Operators
  - Audit Log
- API base URL is configured via `VITE_API_BASE_URL` or `VITE_API_URL`.
- Websocket base URL is configured via `VITE_WS_BASE_URL`.

## Agent Readiness

- Go agent builds with `go build ./...`.
- Dev mode remains:
  - `go run . -config ./local-agent.config.json`
  - `go run . -config ./local-agent.config.json -once`
- Windows service commands exist:
  - `install`
  - `uninstall`
  - `start`
  - `stop`
  - `status`
- Windows config path:
  - `C:\ProgramData\TechiAgent\agent.config.json`
- Windows log path:
  - `C:\ProgramData\TechiAgent\logs\agent.log`
- Agent version marker is `1.0.0`.
- Process, service, and software inventory remain disabled by default.

## Database Readiness

- Alembic migrations are present under `backend/alembic/versions`.
- Run migrations before internal deployment:
  - `cd backend`
  - `alembic upgrade head`
- Current default database URL is SQLite:
  - `sqlite:///./techi.db`
- SQLite is acceptable for local/internal pilot use only.
- PostgreSQL production migration is not part of V1.0.

## Security Readiness

- JWT auth is enabled.
- Required production secret:
  - `SECRET_KEY` or `JWT_SECRET`
- Bootstrap owner password should be provided with:
  - `BOOTSTRAP_OWNER_PASSWORD`
- Role model:
  - owner
  - admin
  - operator
  - readonly
- Uploading agent packages is restricted to admin/owner.
- Downloading inactive packages is restricted to admin/owner.
- Scoped access is enforced for non-admin operators where scope dependencies are used.
- No arbitrary shell execution is enabled.

## Deployment Readiness

- Backend startup:
  - `cd backend`
  - `uvicorn app.main:app --host 0.0.0.0 --port 8000`
- Frontend dev startup:
  - `cd frontend`
  - `npm install`
  - `npm run dev`
- Frontend production build:
  - `cd frontend`
  - `npm run build`
- Agent dev heartbeat:
  - `cd agent`
  - `go run . -config ./local-agent.config.json -once`
- Windows service install:
  - build or place `techi-agent.exe`
  - open PowerShell as Administrator
  - `.\techi-agent.exe install -config C:\ProgramData\TechiAgent\agent.config.json -enrollment-token <TOKEN>`
  - `.\techi-agent.exe start`
  - `.\techi-agent.exe status`
- Windows bootstrap:
  - Generate script from Enrollment Bootstrap page.
  - Run as Administrator.

## Environment Config Audit

Do not commit real secret values.

Backend:

- `SECRET_KEY` or `JWT_SECRET`
  - Required for stable JWT signing across restarts.
- `BOOTSTRAP_OWNER_USERNAME`
  - Optional; defaults to `owner`.
- `BOOTSTRAP_OWNER_EMAIL`
  - Optional; defaults to `owner@localhost`.
- `BOOTSTRAP_OWNER_PASSWORD`
  - Required for first owner bootstrap in real deployment.
- `DATABASE_URL`
  - Defaults to `sqlite:///./techi.db`.
- `BACKEND_CORS_ORIGINS`
  - Comma-separated list of frontend origins.
- `AGENT_PACKAGE_STORAGE_DIR`
  - Defaults to `agent_packages`.
- `HEARTBEAT_TIMEOUT_SECONDS`
  - Defaults to `300`.
- `RECONCILIATION_INTERVAL_SECONDS`
  - Defaults to `30`.

Frontend:

- `VITE_API_BASE_URL` or `VITE_API_URL`
  - Example: `https://msp.example.com`
- `VITE_WS_BASE_URL`
  - Example: `wss://msp.example.com`
- `VITE_REALTIME_DEBUG`
  - Optional; use `true` only for debugging.

Agent:

- `TECHI_API_URL`
  - Optional base URL override.
- `TECHI_BACKEND_URL`
  - Optional direct heartbeat endpoint override.
- `TECHI_ENROLLMENT_TOKEN`
  - Optional first-run enrollment token override.

## Health Checks

- API health:
  - `curl -sS http://127.0.0.1:8000/health`
- DB migration status:
  - `cd backend`
  - `alembic current`
  - `alembic heads`
- Frontend build:
  - `cd frontend`
  - `npm run build`
- Agent heartbeat:
  - `cd agent`
  - `go run . -config ./local-agent.config.json -once`
- Websocket:
  - Open Dashboard or Devices page and confirm realtime indicator reaches connected state.
  - Backend websocket path: `/ws/devices?tenant_id=default`.

## Known Limitations

- No arbitrary shell execution.
- No MFA yet.
- SQLite remains the default local database; PostgreSQL production migration is not part of V1.0.
- No code signing for agent binaries yet.
- No auto-update system yet.
- No CDN/S3/object storage for packages yet; package registry uses local filesystem storage.
- No multi-node websocket/pubsub yet; realtime is single-node.
- Process, service, and software inventory are disabled by default for privacy.
- Windows service deployment requires Administrator privileges.
- Package download URLs are protected by JWT auth; fully unauthenticated installer download flow is not part of V1.0.
