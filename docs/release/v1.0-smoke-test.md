# TECHI Platform V1.0 Smoke Test

Use this after migrations and startup are complete. Do not use production secrets in screenshots or logs.

## 1. Start Services

Backend:

```bash
cd backend
alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Frontend:

```bash
cd frontend
npm run dev
```

Agent dev mode:

```bash
cd agent
go run . -config ./local-agent.config.json -once
```

## 2. Health Checks

- Open `http://127.0.0.1:8000/health`.
- Expected response includes `"status": "ok"`.
- Run:

```bash
cd backend
alembic current
alembic heads
```

- Confirm current revision matches a head revision.

## 3. Login

- Open the frontend.
- Login with the bootstrap owner or an existing owner/admin account.
- Confirm Dashboard loads.

## 4. Create Operator

- Go to Operators.
- Create a test operator.
- Expected:
  - operator appears in the list
  - role is shown correctly
  - audit entry is created

## 5. Assign Scope

- As owner/admin, assign client/group/device scope to an operator.
- Login as that operator.
- Expected:
  - Devices view only shows scoped resources
  - restricted admin pages are not available when role does not allow them

## 6. Enrollment Token

- Create an enrollment token.
- Copy the plaintext token value at creation time.
- Expected:
  - token is active
  - use count starts at zero

## 7. Bootstrap Generation

- Go to Enrollment Bootstrap.
- Select the active token.
- Choose Windows.
- Generate bootstrap.
- Expected:
  - script is generated
  - warning says to run as Administrator
  - backend URL is shown
  - selected token is shown
  - if an active `windows-amd64` package exists, script uses its download URL
  - otherwise script uses `<TECHI_AGENT_WINDOWS_EXE_URL>` placeholder

## 8. Agent Package

- Go to Agent Packages.
- Upload a test package as admin/owner.
- Activate the package.
- Download it.
- Login as readonly/operator.
- Expected:
  - active package is visible and downloadable
  - upload controls are not shown
  - upload API returns 403 if called directly

## 9. Enroll Device

- Run the agent with a config containing a valid enrollment token, or use the generated Windows bootstrap script on a test VM.
- Expected:
  - agent receives `agent_id` and `device_id`
  - local config persists identity
  - enrollment token use count increments
  - device appears in Devices

## 10. Heartbeat

- Run:

```bash
cd agent
go run . -config ./local-agent.config.json -once
```

- Expected:
  - backend accepts heartbeat
  - `last_seen` updates
  - device status/freshness updates
  - Dashboard and Devices update via realtime or fallback refresh

## 11. Maintenance Mode

- Open a device drawer.
- Enter maintenance mode.
- Clear maintenance mode.
- Expected:
  - maintenance badge appears and clears
  - audit log records the operations

## 12. Archive / Restore

- Archive a non-critical test device.
- Switch lifecycle filter to archived.
- Restore the device.
- Expected:
  - active list hides archived device unless lifecycle filter allows it
  - restore returns it to active list
  - audit log records archive and restore

## 13. Remote Action Ping

- Queue a `ping` action for an enrolled test device.
- Run agent heartbeat loop or `-once`.
- Expected:
  - action transitions through queued/sent/acknowledged/running/completed
  - recent actions update in UI
  - audit/device activity reflects the action

## 14. Audit Log

- Go to Audit Log.
- Filter by action/operator/entity type.
- Expand details row.
- Expected:
  - recent operator and device lifecycle events are visible
  - details JSON is readable

## 15. Websocket

- Open Dashboard or Devices.
- Confirm realtime status shows connected.
- Trigger a heartbeat.
- Expected:
  - device row/card patches quietly
  - no full page jump
  - selected filters/tree state remain stable

## Pass Criteria

- Backend health is OK.
- Migrations are at head.
- Frontend builds.
- Agent builds and can send a heartbeat.
- Login, operator creation, scoped access, enrollment, heartbeat, maintenance, archive/restore, remote action ping, audit log, bootstrap, and package download complete without unhandled errors.
